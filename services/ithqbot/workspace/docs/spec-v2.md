# thqbot 产品需求文档 v2

## 1. 背景

团队需要把 AI 能力接入内部系统，但现有工具彼此割裂：对话在一个系统、技能执行在另一个系统、
任务编排又依赖人工。我们希望交付一个统一入口，并让"系统正在做什么"对用户可见。

## 2. 目标

- 提供 Web 端对话入口，支持多轮上下文。
- 支持调用技能（skills）完成具体任务，并展示调用了哪些技能。
- 消息链路可横向扩展，重启不丢消息。
- 关键过程实时可见，而不是等最终结果。

## 3. 范围

### 3.1 包含

- 单点登录与会话管理。
- 会话列表与消息记录，消息持久化到 PostgreSQL。
- 技能调用（文本类技能优先）与技能调用进度展示。
- 实时推送通道。

### 3.2 不包含

- 移动端原生应用。
- 计费与配额。
- 对象存储与附件上传。

## 4. 技术方案

- 前端：React 单页应用，通过 SSE 接收实时事件。
- 后端：无状态服务，负责鉴权、会话与消息存储，会话数据以 PostgreSQL 为唯一事实来源。
- 消息骨干：Kafka 解耦接入与执行，消费端使用 earliest 偏移并做幂等去重。
- 存储：Redis 仅承担缓存、去重与推送通道，不再是会话主存储。

## 5. 交互

1. 用户登录后进入会话列表。
2. 选择会话，输入消息并发送。
3. 系统异步执行，前端通过 SSE 实时接收进度与技能调用信息。
4. 最终结果与过程中的技能调用记录一起写入会话记录。

## 6. 指标

- 单条消息端到端延迟低于 5 秒。
- 消息不丢失，网关重启期间产生的回复可回放。
- 技能调用可见率 100%。
