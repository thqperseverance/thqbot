# ithqbot Engine 需求文档 (PRD)

本文档定义了 **ithqbot (Agent Engine)** 的核心功能需求，旨在构建一个强大、可扩展且完全解耦的 AI 智能体执行环境。

## 1. 核心目标

- **高效推理**：支持长对话、复杂任务链的多步推理。
- **租户隔离**：在物理存储和逻辑记忆上实现完全的 `tenant_id` 隔离。
- **协议兼容**：遵循 **ithqbot v1.2 协议**，作为无状态 Worker 处理 Kafka 任务。
- **技能扩展 (Skills)**：允许动态加载业务插件（Skill），而无需修改引擎核心代码。

## 2. 功能需求

### 2.1 消息处理 (Messaging)
- 引擎应能接收并解析标准的 Kafka 入站报文。
- 自动提取并注入 `account_id`、`chat_id`、`tenant_id` 等运行时上下文变量。
- 处理完成后推送结构化回复（含富文本、附件、元数据）。

### 2.2 会话与记忆 (Session & Memory)
- **多端共享**：同一 `(tenant_id, account_id, chat_id)` 下的所有终端共享 AI 记忆上下文。
- **持久化隔离**：对话历史必须按租户索引，防止跨租户越权访问。
- **Token 统计**：按用户和机器人维度实时统计 LLM 的消耗情况。

### 2.3 任务路由 (Model Routing)
- **两阶段路由**：第一阶段使用小模型（Small Model）进行意图识别与复杂度评估，第二阶段根据路由结果选择合适的模型（Small/Medium/Large）执行任务。
- **自动升档**：当处理失败或低置信度时，自动升级到大参数量模型重试。

### 2.4 安全护栏 (Bot Guardrails)
- **工具白名单**：按机器人（`bot_id`）配置允许调用的工具清单。
- **内容审查**：对入参指令进行正则匹配，对出参内容进行敏感词审查。
- **拦截响应**：命中护栏规则时，返回友好的拦截文案而非大模型生成的原内容。

### 2.5 技能框架 (Skill Framework)
- 支持 `SKILL.md` 标准定义的技能发现与加载。
- 自动将运行时上下文透明注入到 Skill 内部，Skill 开发者无需关注如何获取当前用户身份。

## 3. 非功能需求

- **高可靠性**：支持 Kafka 消费偏移量自动提交，确保重启不丢消息。
- **水平扩展**：支持弹性增加 Engine 副本以应对突发流量。
- **可观测性**：全链路提供 Trace 日志，特别是每一个 Skill 的执行进度和结果。
